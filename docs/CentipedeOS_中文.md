# CentipedeOS

CentipedeOS（全称 Centipede Operating System）是一个计划在中短期内打造的 Linux 发行版项目，基于 Fedora，采用 Kickstart 和 RPM 软件包。

## 理念

> “万物皆可建造……也可尽情拆毁，哪个更有趣就选哪个。”——可逆、灵活、自由（RFF）

## 目标是什么？

CentipedeOS 希望成为一个灵活、实用的环境，服务于软件开发者和网络安全爱好者，同时保持易用与安全。为此，这个发行版应当：

- 提供让各级开发者都更轻松的工具，从初级工程师到软件架构师；
- 支持网络安全方向的研究与实验。

最终的成果是一台工作站：你可以在上面开发应用，同时随时创建隔离环境来做安全实验，包括那些可能从操作系统一路破坏到硬件的实验。操作自由是 Centipede 理念的核心。不妨把它看作计算机工程的“沙盒”：用户可以构建软件、拆解系统、搭建网络、测试恶意代码、尝试各种配置，然后随时回到一个已知的、预先设定好的状态。

我们的想法不是像 Windows 和 macOS 那样限制用户的操作。相反，Centipede 让用户自己决定做还是不做；当用户决定继续时，系统会自动创建隔离环境来运行测试，保障操作安全。

## 背景

本系统的首要目标之一，是为偏爱 Kali Linux 的人提供一个新的选择。Kali 的文档明确说明它是为渗透测试而设计的，并且已经能在多种环境中运行：物理机、虚拟机、容器、云、WSL 等等。需要强调的是，Centipede 并不打算取代 Kali，而是要提供一套舒适的基础设施，完整支持 Kali 的全部工具库。

## 象征意义

“Centipede”是葡萄牙语 *centopeia*（蜈蚣）的英文名。蜈蚣是肉食性节肢动物，许多种类体型大且有毒。选择如此危险的生物作为象征，体现了系统同样具备高度的适应性与模块化。正如蜈蚣拥有毒液和制服猎物的手段，这个发行版也配备了能够执行潜在攻击性操作的工具。

## 环境隔离

环境隔离是操作系统架构的基石。用户获得的自由越多，保护其环境的机制就必须越精密。这也关系到健壮性：这里的健壮性是指，允许激进的实验，而不会让局部故障演变成系统级故障。系统同样**不能**强制规定唯一的工作方式。

## 第 0 层：核心（Core）

**操作系统的基础**

这一层提供发行版运行所需的基本机制。其他所有层都直接或间接依赖它。

### 0.1. 内核与硬件管理

负责操作系统与机器物理部件之间的通信。

- CPU、内存和进程管理。
- USB、PCI 及外设管理。
- 驱动与内核模块管理。
- 电源管理与休眠状态。
- 硬件虚拟化支持。
- 通过 IOMMU 控制设备访问。

**技术：** Linux Kernel、KVM、udev、systemd-udevd、固件和微码。

### 0.2. 服务管理与启动

负责系统的启动，以及后台服务的控制。

- 系统启动与关机。
- 服务与守护进程管理。
- 服务间依赖控制。
- 用户、用户组与会话管理。
- 服务恢复与重启。
- 计划任务执行。

**技术：** systemd、systemd-logind、systemd-tmpfiles 和 systemd-resolved。

### 0.3. 网络管理

提供连接能力，并控制系统与其他网络之间的通信。

- 以太网和 Wi-Fi 接口管理。
- IPv4 和 IPv6 地址配置。
- DNS 和 DHCP 管理。
- 数据包路由。
- VPN 管理。
- 虚拟接口的创建与管理。
- 流量控制与防火墙规则。

**技术：** NetworkManager、iproute2、nftables、firewalld 和 WireGuard。

### 0.4. 存储管理

负责控制存储设备并组织数据。

- 磁盘与分区管理。
- 文件系统的挂载与卸载。
- 卷加密。
- 逻辑卷管理。
- 数据完整性检查。
- 权限与存储配额管理。
- 快照与恢复机制支持。

**技术：** LUKS、LVM、Btrfs、XFS、ext4 和 Stratis。

### 0.5. 系统安全

提供保护与访问控制机制，供其他各层使用。

- 权限与特权控制。
- 进程隔离。
- 强制访问控制（MAC）。
- Linux Capabilities 管理。
- 事件审计。
- 凭据保护。
- 完整性校验。
- Secure Boot 支持。

**技术：** SELinux、seccomp、Linux Capabilities、auditd、PAM、polkit 和 Secure Boot。

### 0.6. 软件包管理与更新

负责系统组件的安装、维护和更新。

- 软件包的安装与卸载。
- 依赖管理。
- 软件源管理。
- 签名与完整性校验。
- 版本控制。
- 更新历史。
- 视所采用的机制而定，支持回滚更改。

**技术：** RPM、DNF5、自建软件源和 GPG 签名。

### 0.7. 日志、诊断与可观测性

负责记录事件，并提供系统运行状况的信息。

- 系统事件日志。
- 服务监控。
- 故障识别。
- 启动与关机记录。
- 变更审计。
- 诊断信息收集。

**技术：** journald、auditd 和 systemd-coredump。

### 0.8. 兼容性与集成

提供系统组件之间通信所需的接口和库。

- 共享库。
- 服务间通信。
- 应用与系统组件的集成。
- 证书管理。
- 区域与时间设置。

**技术：** glibc、D-Bus、OpenSSL 以及 Fedora 生态系统的组件。

- Go。

### 2.2. IDE 与编辑器

## 第 3 层：安全（Security）

**网络安全工具**

这一层提供用于安全分析、审计、调查和评估的专业工具。

第 0 层提供的是操作系统自身的防护机制，而这一层不同：它提供的是建立在这些机制之上、用于开展安全工作的工具。

### 3.1. 网络分析

- 数据包捕获与分析。
- 协议检查。
- 设备发现。
- 网络测绘。
- 流量分析。
- 通信监控。

**技术：** Wireshark、TShark、tcpdump、Zeek、Suricata 和 Nmap。

### 3.2. Web 应用安全

- Web 漏洞分析。
- API 安全测试。
- HTTP 请求检查。
- 配置不当识别。
- 认证机制评估。

**技术：** OWASP ZAP、Burp Suite 和 Nikto。

### 3.3. 渗透测试与攻击性安全

- 系统侦察。
- 服务枚举。
- 漏洞评估。
- 配置测试。
- 防护机制验证。
- 在授权环境中模拟攻击。

**技术：** Metasploit、Nmap、sqlmap 以及 OWASP 生态系统的工具。

### 3.4. 逆向工程

- 二进制文件分析。
- 可执行文件反汇编。
- 反编译。
- 代码分析。
- 底层调试。
- 应用行为研究。

**技术：** Ghidra、Radare2、Cutter、Binary Ninja 和 GDB。

### 3.5. 恶意软件分析

- 静态分析。
- 动态分析。
- 入侵指标（IOC）识别。
- 行为研究。
- 持久化分析。
- 通信机制识别。

**技术：** YARA、capa、Ghidra 和 Volatility。

> 潜在危险样本必须在第 4 层的隔离环境中运行。

### 3.6. 数字取证

- 证据获取。
- 磁盘分析。
- 文件恢复。
- 文件系统调查。
- 内存分析。
- 时间线构建。
- 日志调查。

**技术：** Autopsy、The Sleuth Kit、Volatility、Plaso 和 Wireshark。

### 3.7. 系统与基础设施安全

- 配置审计。
- 权限分析。
- 加固评估。
- 暴露服务识别。
- 合规性检查。
- 安全策略分析。

**技术：** Lynis、OpenSCAP 和 osquery。

### 3.8. 应用与代码安全

- 静态代码分析（SAST）。
- 依赖分析（SCA）。
- 泄露凭据检测。
- 漏洞扫描。
- 容器镜像检查。
- 与开发流水线集成。

**技术：** Semgrep、Gitleaks、Trivy、Grype 和 OWASP Dependency-Check。

### 3.9. 监控与事件响应

- 活动监控。
- 可疑行为检测。
- 事件关联。
- 事件调查。
- 进程监控。
- 证据收集。

**技术：** Wazuh、osquery、Falco 和 Elastic Stack。

### 3.10. 密码学与身份

- 加密密钥管理。
- 证书的创建与验证。
- 身份管理。
- 公钥基础设施（PKI）。
- 机密保护。
- 多因素认证。

**技术：** OpenSSL、GnuPG、age 和 Vault。

## 第 4 层：实验室（Labs）

**隔离的实验环境**

这一层提供创建、运行、监控、恢复和销毁实验环境所需的基础设施。

这是本发行版的主要特色之一：潜在危险的活动可以在受控环境中进行，从而降低主系统被攻破的可能性。

### 4.1. 虚拟化

- 创建虚拟机。
- CPU 与内存管理。
- 虚拟磁盘管理。
- 硬件模拟。
- 机器克隆。
- 嵌套虚拟化（nested virtualization）。
- 虚拟设备管理。

**技术：** KVM、QEMU 和 libvirt。

### 4.2. 虚拟网络

- 创建隔离网络。
- 虚拟接口管理。
- 网络分段。
- 拓扑模拟。
- 创建虚拟路由器和交换机。
- 控制机器之间的通信。
- 模拟延迟与丢包。

**技术：** libvirt networks、Linux bridges、Open vSwitch、nftables 和 tc。

### 4.3. 快照与状态管理

- 创建还原点。
- 回滚到之前的状态。
- 环境克隆。
- 状态对比。
- 配置版本化。
- 保存实验状态。

**技术：** QEMU/libvirt 快照和 Btrfs。

> 请注意：快照不能替代备份。它们可以让你回到特定状态，但无法防止物理存储的丢失或损坏。

### 4.4. 隔离环境

- 创建一次性环境。
- 主机与实验环境分离。
- 文件系统隔离。
- 文件共享控制。
- 限制设备访问。
- 独立的凭据管理。
- 限制计算资源。

**技术：** Podman、KVM、namespaces、cgroups 和 SELinux。

### 4.5. 模板与部署

- 虚拟机模板。
- 基础镜像。
- 预设配置。
- 自动化安装。
- 网络部署。
- 复现实验环境。
- 按需创建实验室。

**技术：** cloud-init、Kickstart、Ansible、Packer 和 OCI 镜像。

### 4.6. 专业实验室

可以为安全和开发的不同方向提供预先配置好的环境。

- Web Security Lab。
- Network Security Lab。
- Malware Analysis Lab。
- Reverse Engineering Lab。
- Digital Forensics Lab。
- Red Team Lab。
- Blue Team Lab。
- Vulnerable Applications Lab。
- OS Research Lab。
- Kernel Development Lab。

每个实验室都可以有自己的工具、网络配置、访问策略和计算资源。

### 4.7. 威胁与攻击模拟

- 模拟恶意流量。
- 模拟系统被入侵。
- 在受控环境中进行利用测试。
- 模拟服务中断。
- 模拟虚拟机之间的横向移动。
- 检测与响应测试。
- 研究类似恶意软件的行为。

> 这些活动只能在经过妥善隔离并获得授权的实验环境中进行。

### 4.8. 实验室可观测性

- CPU 与内存监控。
- 网络流量监控。
- 进程记录。
- 事件收集。
- 活动历史。
- 证据保存。
- 环境行为分析。

**技术：** journald、Wireshark、tcpdump、Prometheus 和 Grafana。

### 4.9. 恢复与销毁

- 恢复快照。
- 销毁环境。
- 自动化重建。
- 清理虚拟磁盘。
- 移除临时网络。
- 销毁前保存证据。
- 实验结束后验证主机状态。

### 4.10. 实验室安全策略

- 控制对主系统的访问。
- 控制对本地网络的访问。
- 限制互联网访问。
- 共享文件夹管理。
- USB 设备控制。
- 剪贴板控制。
- 限制实验室之间的通信。
- 限制计算资源。
